## Research Notes

- Blender Manual "Input Fields" (fetched earlier, verified): number
  fields draw hover arrows `<` `>`, drag-scrub with Ctrl snap / Shift
  precision -- already replicated in our NumberField.
- Blender Manual structure lists dedicated widget chapters: Buttons,
  Popups (dropdowns), Widgets. Widget conventions (from the manual and
  the Blender 2.8+ design spec lineage):
  - **Sliders**: the whole track is the control; a filled bar shows the
    value; hover reveals `<` `>` steppers; drag anywhere on the track.
  - **Dropdowns**: a button showing the current value; clicking opens a
    styled popup list; never the OS native menu.
  - **Checkboxes**: small square with a check mark, label to the side.
  - Everything shares one dark theme: exact paddings, 3px radii, hairline
    borders, monospaced numerals.
- Web precedents (Figma, rive, spline): editors avoid native `<input>`/
  `<select>`/`<range>` chrome entirely; popups are DOM; native dialogs
  appear only where the OS provides superior UX (file pickers, color
  dialogs via hidden input trigger).

## Scope

Custom widget library `src/ui/widgets.tsx`:
`Slider`, `Dropdown`, `Toggle`, `ColorSwatch` -- all div/pointer based,
keyboard accessible (role/aria), consistent tokens. Replace every native
control above. Native color popup is retained behind a styled swatch
button (OS color dialog is a native-strength UX; in-page chrome removed).

## Test impact (planned updates)

- Value-setting tests that used native range `evaluate` setters move to
  track-click helper `setSlider()`.
- `selectOption` tests move to dropdown button + option click.
- `check()`/`toBeChecked` move to aria-checked assertions.
- `.inspector-slider-value` text span is preserved inside Slider so
  text-based assertions survive.
